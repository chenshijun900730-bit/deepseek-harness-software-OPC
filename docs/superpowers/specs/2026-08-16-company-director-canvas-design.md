# 软件公司 Harness v2 · 总监可视化串并联开发模式 —— 设计规格

- **日期**：2026-08-16
- **状态**：已与用户逐节确认（§1–§5 全部确认，含交互演示 v2 定稿）
- **范围**：在现有 `software-company` preset（`~/.dsh/.agent-presets/software-company/`，包 `company-r2`）之上，把「线性黑箱流水线」升级为「串并联可视化的公司」

---

## 0. 背景

现状（已核实的实现）：
- 14 个角色定义在 `roles/ROLES.md` / `roles.json`；host 包 `company-r2/host.js`（1339 行）已含代码状态机、组队查表、`/company-api/*` 数据路由（dashboard/task/tokens/agents/action）
- 浏览器面板 `company-r2/client.js` 是右上角浮动胶囊：任务卡（**一条 17 步线性进度条**）、Token 采样、子代理日志
- 任务数据是文件态：`.company-harness/tasks/TASK-*/`（RUN_STATE.json、SPRINT_PLAN.md、COST_LEDGER.md、HANDOFF.md…）
- 用户的痛点：**黑箱** —— 部门间流转、并行工作、交接文档、token 归属都看不见；流程只有串联没有并联

本设计把流程改造成「部门节点 + 串并联流转图 + 交接契约 + 总监实时画布」，并落地五项 token 优化（五刀）。

## 1. 目标与成功标准（§1，已确认）

**一句话**：把「线性黑箱流水线」改造成「串并联可视的公司」——总监在大画布上实时看到部门流转、交接契约、token 消耗，并拥有招聘/改造部门的能力。

### 1.1 目标
1. **串并联开发**：部门真实并行干活（并发上限总监可调，默认 3，复杂任务默认 2）；流程 = 标准模板 + 总监可调，调整全程留痕
2. **流转可见**：部门间每次交接都有「交接契约」，画布箭头上可见、可点开
3. **总监视角**：大画布 + 悬停信息卡 + 实时事件流；画布内直接审批、决策
4. **Token 透明**：按部门/任务/时段真实消耗；五刀优化让流程本身省 token
5. **创造模式**：用 DSH 创造模式能力招聘新部门、改造部门（创建/编辑部门 preset）

### 1.2 成功标准（验收逐条打钩）
- **V1 并行可见**：复杂任务前端/后端/数据三路并行，画布上三个节点同时亮「工作中」，完成后三路交接汇入集成
- **V2 交接可见**：部门完成环节 → 生成交接契约 → 画布对应箭头出现 📄 → 悬停看摘要、点击看全文 → 接收部门签收后状态翻转
- **V3 总监可干预**：画布上暂停/恢复/终止任务、调并发上限、审批门禁、⚖ 决策；模板调整留痕
- **V4 Token 口径**：每部门累计+本轮消耗、全公司总量与趋势；数值来自真实计量（tokenMeter + sessionQuery 按派工记录归属），估算处明确标注；数字以线性补间平滑滚动
- **V5 招聘**：跑一次「招聘自动化测试部」→ 生成新 preset 并注册 → 画布出现新节点 → 可正常派工
- **V6 兼容**：现有 4 个任务文件（TASK-001…004）仍可读；旧 `company_*` 工具名不变
- **V7 省钱**：同一复杂任务对比五刀改造前后，token 至少降 20%（现实估计）

### 1.3 非目标（YAGNI）
不做多公司并存；不做手机端；不做预算自动扣费/硬限额（只做阈值提醒）；不做自然语言问答式看板查询。

## 2. 执行引擎（§2 + 五刀，已确认）

### 2.1 三层结构
| 层 | 谁 | 职责 | 用 LLM 吗 |
|---|---|---|---|
| 总监会话 | 主会话（用户） | 提需求、批门禁、看画布；LLM 只做**分类裁决 + 冲突裁决 + 沟通** | 少量；裁决瞬间升 max |
| 公司引擎 | Host 代码状态机 | 组队查表、状态推进、派工路由、并发名额、事件流、台账、契约生成——全部代码 | 否 |
| 部门子代理 | 14+1 角色 | 每次派工 = 新上下文子代理 + 注入「部门档案」+ 契约切片；做完由代码写回档案 | 是 |

**裁决的实现方式**（DSH 约束：主会话模型档位不可动态切换）：裁决点 spawn 独立子代理（`deepseek-v4-pro` / `max`），只在争议瞬间存在；画布以瞬时 ⚖ 节点呈现，事后折叠进事件流。

### 2.2 流程：线性 → DAG 模板
- 每个任务一张流转图：节点 = 部门环节，边 = 交接；模板按类型（小型/中型/复杂/高风险），总监可调（加并行分支/插环节/跳环节），调整写进 RUN_STATE 并留痕
- 复杂任务默认：产品 → 架构 →〔前端 ‖ 后端 ‖ 数据〕→ 集成 → QA → 验收 → 发布
- 并发上限：总监可调（2/3/4，默认 3）；**复杂任务默认 2**（五刀修正）；高风险评审与编码不得在同一未冻结代码状态下并发

### 2.3 事件流（画布唯一数据源，零 token）
状态机每个变化 append 一条事件到 `events/events.jsonl`：
`task.created / stage.started / stage.progress / stage.done / handoff.issued / handoff.signed / review.pass|fail / adjudication.* / repair.* / paused|resumed|terminated`
画布每 2s 增量拉取 + 前端线性补间。

### 2.4 交接契约三件套（替代散文 HANDOFF）
1. **模块图**（mermaid）：模块边界 + 文件所有权（共享表面仅 Integrator 可改）
2. **类型化 API 签名**：路径、字段、类型、owner
3. **非目标清单**
- 按角色切切片注入（不注入全量蓝图）
- 确定性断言（测试/lint/覆盖率/构建）由脚本跑，作为徽章进事件流
- 接收部门签收后箭头/契约状态翻转

### 2.5 评审与失败回路（保留的护城河）
- 小型/中型：sprint-evaluator 发布轮 + 全量确定性套件毕业；**final-evaluator 只留给复杂/高风险**（中型语义/UX 验收标准无法全确定性验证时仍保留一次独立终验）
- security-reviewer 仅在权限/支付/迁移触发（已有 H-04 判定）
- FAIL → 全新上下文 Repair Generator（报告只带 **diff + 失败断言 + 最小复现**）→ 2 修 1 重规划 → PAUSED 通知总监。**一律保留**
- Sprint Evaluator 独立上下文保留（防自审盲区）

### 2.6 五刀落点清单
| 刀 | 内容 | 状态 |
|---|---|---|
| ① Coordinator 状态机化 | 组队/派工/状态推进/统计全部代码；LLM 仅分类+冲突裁决（瞬时 max 子代理） | 采纳 |
| ② Recorder 代码化 | RUN_STATE/证据索引/台账/交接档案程序化写入；仅收尾摘要调一次 flash | 采纳 |
| ③ 评审 checklist 代码化 | 确定性断言跑脚本；中型砍 final-evaluator（保守修正见 2.5）；security 严格触发 | 采纳（含修正） |
| ④ reasoning 分档 | mechanical-worker/recorder → low；**qa-runner/explorer → medium**（修正：不降 low，保证据链） | 采纳（含修正） |
| ⑤ 交接换契约三件套 + 调查缓存 | 见 2.4；Explorer 调查按仓库哈希存 `.company-harness/explorations/<hash>.json` 复用 | 采纳 |

### 2.7 招聘/改造（详见 §4）
`company_hire_department` / `company_upgrade_department` 工具 + 画布入口。

### 2.8 文件布局新增
```
.company-harness/
  departments/<id>.md      部门档案（跨任务记忆，派工注入）
  events/events.jsonl      事件流
  explorations/<hash>.json 调查缓存
  templates/flows/*.json   标准流程模板（含总监调整留痕）
  tasks/TASK-*/…           原有任务文件不变（V6 兼容）
```

## 3. 总监大画布（§3，交互演示 v2 定稿）

### 3.1 胶囊（DSH 右上角浮动，替换现有 Company 胶囊）
一眼状态：`🏢 Company · N 项目 · ⚙ M 工作中 · ⚡ token 总量 · 🔴 卡住数`；点击进入全屏画布页 `/company`。

### 3.2 全屏画布页（host `webServer` 注册路由 `/company`，与 `/company-api/*` 同源）
| 区域 | 内容 |
|---|---|
| 顶栏 | 公司 token 总量+趋势迷你线（数字线性补间跳动）· 并发上限滑杆（2/3/4，可直接点）· 项目 chips（点击聚焦该项目流转图）· 「＋招聘部门」· 🔔 待批准铃铛 |
| 画布主体 | 节点=部门（颜色=状态），实线箭头=流转/交接，📄=交接契约，黄色虚线=总监派工，红色虚线=失败路由，⚖=瞬时裁决节点；**可缩放、拖拽、自动布局**；任务多时按项目分图层 |
| 右侧栏（可收起） | ⑤ 实时事件流（滚动）+ ④ 交接契约列表（点开全文）|

### 3.3 交互（v2 定稿细节）
- **悬停信息卡**（自动弹出在节点旁边，自动避让不遮挡：右侧放不下翻左侧、底部放不下上移）：状态+当前任务 · 进度条 · 本轮/累计 token+部门排名 · 最近交接（收/发）· 排队队列 · 模型/reasoning 档位；📄 悬停显示契约摘要
- **拖动**：按住任意节点直接拖动，**所有连线与 📄 图标实时跟随**（连线由节点位置计算）；「⟲ 自动布局」一键复位；拖动与点击区分（拖动不触发抽屉）
- **工作部门可视化**：工作中节点 = 紫色呼吸光晕 + 流光扫过；排队=蓝、空闲=灰、卡住=红、完成=绿、待批准=琥珀
- **写入动态**：工作部门每隔数秒弹出「✍ 文件 +N 行」浮动气泡，事件流同步滚动（v1 数据来自引擎事件流：子代理完成写入经证据索引汇总成 `stage.progress` 事件；DSH 若提供 fs 写事件则作为增强项 hook）
- **Token 数字**：2s 拉取真实值 + 前端线性插值平滑滚动跳动（非生硬跳变）
- **点击节点** → 右侧部门抽屉：档案摘要、历史任务、token 曲线、派工记录、「⚙ 改造」
- **点击 📄** → 契约全文浮层（模块图/API 签名/非目标 + 签收状态与签名人）
- **画布内直接审批**：🔔 → 右侧审批面板（任务摘要+合同摘要+✅ 批准并派工 / ❌ 拒绝退回）；批准=自动组队派工，拒绝=退回 INTAKE 重新分类；动作写回引擎+事件流
- **画布内直接决策**：⚖ 节点 → 决策面板多方案点选（如并发冲突：A 排队等待 / B 提上限至 4 / C 暂停该部门）；决策后 ⚖ 节点变灰「已决策」并折叠进事件流
- **总监操作全集**：暂停/恢复/终止任务 · 调并发上限 · 调模板（加分支/插环节，留痕）· 招聘/改造部门 · 审批门禁 · 冲突决策

### 3.4 视觉语言
深色画布 + 状态色（绿/紫/蓝/灰/红/琥珀）+ 工作节点微光脉冲；数据 2s 增量拉取；**渲染零 token**。

## 4. 招聘/改造部门（§4，已确认）

### 4.1 招聘入口（顶栏「＋ 招聘部门」，三步）
| 步骤 | 内容 |
|---|---|
| ① 定义 | 部门名 + 职责人设（手写或模板：自动化测试部 / DevOps 部 / 文档部 / 前端部…） |
| ② 装备 | 模型档位（pro/flash）+ reasoning（low/medium/high）+ 授权工具集勾选 |
| ③ 挂流程 | 进「可选部门池」，总监拖进某流程模板位置（如 QA 之后），参与后续派工 |

提交后引擎执行：复制部门模板 preset → 生成 `~/.dsh/.agent-presets/company-dept-<id>/` → 注册进 roles.json → 画布出现新节点 → 可派工。全程事件流留痕，可撤销。

### 4.2 改造部门
点节点 → 抽屉「⚙ 改造」→ 改人设/模型/reasoning/工具集（写回 preset 文件 + 部门档案）。**正在跑的任务不受影响**（只影响下次派工），改造记录进事件流。

### 4.3 安全护栏
- 新部门默认**无权**：不授予任何 `company_*` 引擎工具，不能改 RUN_STATE/合同/台账（总监可显式开放）
- 部门 preset 独立目录 `company-dept-<id>`，**永不覆盖 14 个标准角色**
- 招聘/改造前二次确认（显示将写入的文件路径），全部留痕、可撤销（移除注册+归档文件，不物理删除）
- 撤销标准角色、删除正在工作的部门 → 引擎拒绝

### 4.4 与 DSH 创造模式的分工
- 招聘/改造部门 = preset 复制+注册通道（面向业务，总监可操作）
- 改造公司本身（引擎/看板/制度）= 总监会话保留 cordis 工具集（运行时检查、插件实验）

## 5. 数据流与实施分期（§5，已确认）

### 5.1 数据流
```
部门子代理 ──工作──▶ 工作区文件（git worktree）
        │ 回报
        ▼
公司引擎（host 状态机，唯一写入者）──▶ RUN_STATE / 交接契约 / 部门档案 / COST_LEDGER
        │ 每变化 append
        ▼
events/events.jsonl ◀── 画布每 2s 增量拉取 + 前端线性补间 ── 胶囊/全屏画布（只读）
        ▲
tokenMeter + sessionQuery（真实计量）──▶ 按派工记录归属到部门/任务
```
- 画布与胶囊只读；唯一写回 = 总监审批/决策操作（走 `/company-api/action`，引擎校验后改状态机）
- 多会话：复用现有「路由首实例注册 + 文件态任务数据」机制

### 5.2 实施分期
| 期 | 内容 | 验收点 |
|---|---|---|
| **P0 引擎**（改 `company-r2/host.js`，不动 client 注册契约） | DAG 流程模板+总监可调 · 事件流文件 · 交接契约三件套 · 五刀落地 · 复合驱动工具 `company_run_sprint`（一个 LLM 回合驱动阶段链，逼近 50% 节省的进阶项） | V6；一次派工多部门真并行 |
| **P1 画布** | `/company` 全屏页 + 胶囊升级 · 节点拖动/连线跟随 · 悬停信息卡避让 · 工作节点特效 · 写入动态+token 补间 · 画布审批/决策 · 2s 拉取 | V1/V2/V3/V4 |
| **P2 招聘** | 招聘/改造部门（preset 复制+注册+护栏）· 部门档案注入 · Explorer 调查缓存 | V5 |
| **P3 验收** | 五场景验收：① 小型 UI 修改 ② 中型持久化功能 ③ 多模块新功能（并行）④ 注入式 QA 失败（修复回路）⑤ 并发文件所有权冲突（裁决/暂停）；另加一个破坏性操作样例验证自动暂停。五刀前后 token 对比（V7）· Safari 过一遍 · 更新 SKILL.md | V1–V7 全绿 |

## 7. 风险与既定约束

1. `client.js` 的 `__ModuleLoader__.load` 注册契约**保持不动**（HANDOVER.md 第 1 条，勿回退）
2. 包目录**不改名**；若必须改，先提醒用户重启 DSH 进程（幽灵插件历史教训）
3. 画布页走 host `webServer` 路由，与现有 `/company-api/*` 同源，不新增外部服务
4. 所有新文件在 `.company-harness/` 或 preset 包内；`~/.dsh` 之外写入照旧需用户授权
5. 真实 token 节省预期 20–35%（本实现引擎已部分代码化）；要逼近 50% 依赖 P0 的 `company_run_sprint` 复合驱动工具
6. 「写入动态」v1 来自引擎事件流（证据索引），fs 写事件 hook 为增强项
